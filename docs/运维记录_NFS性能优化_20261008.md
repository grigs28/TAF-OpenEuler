# NFS 性能优化运维记录（2026-10-08）

## 背景

月度备份读取链路（生产机 192.168.0.16 ← 群晖 NAS 192.168.0.79，NFSv4.1）单流冷读实测 364 MB/s，客户端预读仅 128KB、单 TCP 连接、RPC 块 128KB。为提升 10/15 月度备份的读取吞吐，实施三层优化。

## 优化内容

### 一、生产机（192.168.0.16）客户端

| 项目 | 修改前 | 修改后 | 持久化 |
|---|---|---|---|
| BDI 预读 | 128KB | 16MB | `/etc/systemd/system/nfs-readahead.service` + `/usr/local/sbin/nfs-readahead.sh`（动态解析挂载点 BDI 编号） |
| TCP 连接 | 1 条/挂载 | `nconnect=8` | `/etc/fstab`（备份：`/etc/fstab.bak.20261008123608`） |
| RPC 块 | 128KB | `rsize=wsize=1048576`（请求） | 同上，待 NAS 侧放开后协商生效 |

fstab 目标行示例：
```
192.168.0.79:/volume1/YZBAK  /mnt/79-yzbak  nfs4  soft,timeo=100,retrans=3,rsize=1048576,wsize=1048576,nconnect=8,_netdev,nofail,x-systemd.device-timeout=10  0 0
```

### 二、群晖 NAS（192.168.0.79）服务端

DSM 将 `/proc/fs/nfsd/max_block_size` 限制在 128KB（内核支持 1MB）。**免重启修改流程**（nfsd 运行时该文件锁定、停服务后整个 `/proc/fs/nfsd` 被卸载，需手动挂回）：

```bash
systemctl stop nfs-server
mount -t nfsd nfsd /proc/fs/nfsd          # 挂回控制接口（不启动 nfsd 线程）
echo 1048576 > /proc/fs/nfsd/max_block_size
systemctl start nfs-server                 # 实测值保留，DSM 不重置
```

持久化：`/etc/systemd/system/nfs-blocksize.service`（After=proc-fs-nfsd.mount、Before=nfs-server.service，WantedBy=nfs-server.service），已 enable。
注意：DSM 大版本更新可能覆盖该 unit，升级后需检查重加。

### 三、客户端重挂载

NAS 放开上限后，`.16` 重挂载两个共享，最终协商 `rsize=1048576,wsize=1048576,nconnect=8`。

## 效果（315MB 文件冷读实测）

| 配置 | 单流 | 双流聚合 |
|---|---|---|
| 优化前 | 364 MB/s | — |
| +预读16MB +nconnect=8 | 686 MB/s | 2.4 GB/s |
| +rsize=1MB（最终） | **1.1 GB/s** | 1.9 GB/s |

热读（页缓存命中）4.7 GB/s 不受影响。TAF 服务全程在线。

## 兼容性验证

- `.19` 旧挂载会话（128KB 参数）在 NAS 改造后依然存活，协商值不变
- `.16` 显式 128KB 新建挂载成功且按其请求协商
- 原理：rsize/wsize 每挂载独立协商 `min(客户端请求, 服务端上限)`，放宽上限对旧客户端零影响

## 回滚方法

- `.16`：恢复 fstab 备份 → `systemctl disable --now nfs-readahead` → 重挂载
- NAS：`systemctl disable nfs-blocksize` → 停服务重挂 nfsd 控制fs 写回 `131072` → 起服务

## 遗留说明

- 真正的备份墙钟瓶颈仍在扫描元数据（710万文件约 9 小时）与压缩/磁带尾段；本次优化提升读取上限约 3 倍，整体时长收益以 10/15 实测为准
